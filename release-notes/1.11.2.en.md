Lets you find the files that still need a look by the kind of problem they
have, walk a video's tracking gaps in order and record the ones you checked,
and keeps the window responsive while files are added. Local logs no longer
carry file names.

## File results

- When a run finishes, **File results…** in the activity area filters the
  attention and failure items by the kind of problem: uncovered regions,
  tracking gaps, tracks dropped automatically or by you, scan failures,
  metadata warnings, output conflicts, processing failures, and output that
  covered nothing. Until now you had to read the activity log to find which
  file went wrong.
- Open an input from the list, or review or reprocess a selected input. Picking
  a gap re-analyses the video and opens review at that frame.
- Reprocessing uses your **current settings** and writes to a new job folder
  under the existing output. It analyses the original from scratch, so earlier
  edits are not kept. The button says the same thing.
- Opening the output folder works only for results that were actually saved.
  Results reset when the next run starts, and files that never started are not
  listed.
- Cancelling a parallel run no longer drops the results of files that were
  already being processed.

## Video review

- Tracking gaps found before review are listed in start-frame order. Each entry
  shows the track number, the time in milliseconds, and a frame range counted
  from 1; selecting one jumps to the first frame of that gap.
- **Previous gap / Next gap** move to the nearest start before or after the
  current position. Gaps that share a start are passed once by the buttons and
  can still be selected individually in the list.
- Left and Right arrow keys, or the buttons beside the timeline, move one frame
  at a time. Changing frames cancels a box you were drawing so it cannot land
  on the wrong frame.
- After looking through a gap you can tick **Reviewed**, which records that you
  checked it and lets you see how many frames are still unchecked. Adding,
  editing, or deleting a mask, or changing whether a track is included, clears
  the ticks. Reviewed is a record of what you looked at, not the app verifying
  that the range ended up covered.
- The red timeline marks and the warnings mean tracking gaps **found before
  review**. Adding a manual mask does not establish where the subject actually
  was, so the warnings stay. Play those ranges yourself before sharing.
- The low-confidence track text now matches what the app does: they are
  included by default. The description said they were excluded, which
  contradicted the checkboxes in the list.

## Result summary and inputs that could not be read

- The summary now separates regions dropped at the detection limit, tracking
  gap frames, dropped tracks, files with metadata warnings, and input paths
  that could not be read. They used to be added into one number that did not
  say what had gone wrong.
- A subfolder that cannot be opened is reported with its exact path, and the
  other readable folders are still scanned. Directory symlinks are not followed
  recursively.

## Adding files

- Photo and video thumbnails are built in the background, at most two at a
  time. The list shows a default icon first and fills in as they are ready.
  Adding a video used to make the window look frozen.
- Thumbnails for entries you removed are discarded. Very large images, and
  images whose size cannot be read, keep the default icon. Skipping a thumbnail
  is not a limit on the processing itself.

## Local logs

- The basic disk log no longer records file names or paths. It keeps
  diagnostics such as whether a run started and how many files ended each way.
- Anything that may contain a file name is written only when you turn on
  **Detailed logging** yourself. It is off by default, and an earlier
  `fileLogging` setting is not carried over as consent to detailed records.
- Log settings apply immediately, and Settings can open the log folder or
  delete the logs. Deleting removes the log file and its rotations only. The
  on-screen activity list is separate from this disk-log policy.

## Model downloads

- A download stops after 30 seconds without a response, or after 15 minutes
  overall including the wait between attempts. A dropped connection, HTTP 429
  or 5xx, and a timeout are retried after one second, up to three attempts in
  total. Cancelling is honoured both while downloading and while waiting to
  retry.
- Cancellation, timeout, network failure, oversize, and integrity failure are
  reported as distinct outcomes. Oversize and integrity failures are not
  retried, and only data that passes the SHA-256 check is stored.
