# M5 2단계: 2패스와 게시 게이트

작성 2026-10-23. [Rust 포팅 계획](RUST_PORT_PLAN.md) 8장 M5 2단계(`m5-render`)의 기록이다. 코드는 core `mask`(`MosaicGrid`, `Region::grid`)·`tracking`(`TrackingWindows` 기본값), engine `video::process`(2패스가 영역 레코드로 마스크), `video::analysis`(`AnalysisSettings::windows`), `run::Note::Tracked`, `batch::LeftOut::Video`, `synthetic::FixedDetection`, CLI `run --videos`(`--mask` 선택 사항, 시험 빌드의 `--fixed-detection`)이다. 시험은 `video_analysis.rs`·`video_export.rs`·`cli_video.rs`·`d7_sessions.rs`와 core `mask` 단위 시험이다.

## 결정(2026-10-23, 메인테이너가 추천대로)

- **추적 창 2초:** 다시 잇는 한도(`max_lost`·`max_since_high`·`max_since_high_moving`), 보간 한도, 장면 전환 경계를 모두 2초로 한다(1.12.1은 1초·1초·1.5초·2/3초·1초, 1단계까지는 보간과 경계만 1초). "보간 한도 = 다시 잇는 한도" 원칙(M5 계획 결정)은 그대로이고 길이만 늘린다. 1–2초 놓친 대상이 새 track이 되어 그 사이 프레임이 경고 없이 드러나던 것을 보간으로 가린다. 근거는 [아래](#p-1영상과-추적-창).
- **P-1(영상) 확인:** 기본 창에서는 미해결 gap이 생기지 않으므로, 게이트는 보간만 1초로 줄인 창(`AnalysisSettings::windows`, CLI에는 없음)으로 실제 FFmpeg 경로에서 확인한다: P-1 fixture 경우(30–64프레임 놓침) → gap 30–64, `NeedsReview`, 출력 폴더 비어 있음. 상한으로 잘린 후보(가짜 감지기)도 같은 게이트를 지난다. P-1 fixture의 영상 경우 문구를 이 설정으로 고쳤다.
- **모자이크 격자:** 영상 track의 모자이크 칸은 영상 좌표에 고정한다. track마다 칸 크기는 그 track에서 가장 큰 padding 영역의 짧은 변 ÷ 강도(올림, 최소 2 px), 칸 경계는 영상 원점에서 칸 크기의 배수, 칸 값은 칸 전체의 평균(영역 밖 pixel 포함, 영상 가장자리에서 잘림). 작은 프레임에서는 칸 수가 줄어 더 강해지고, 강도보다 많은 칸은 생기지 않는다. 사진과 고정 마스크(`--mask`)는 D3 규칙(영역에 맞춘 칸) 그대로다. 근거는 [아래](#모자이크-격자).
- **결과 JSON의 track·gap kind(P-2):** 3단계 세션 형식 2에서 레코드와 함께. 2단계는 CLI 결과 줄에 종류별 track 수("tracked 2 faces and 1 license plate")와 gap 종류("face lost in frames 30–64")를 낸다.

함께 정한 것(질문하지 않음):

- **검토로 남는 영상:** 세션에 넣지 않고 "not kept for review — videos cannot be reviewed yet"으로 알린다(`LeftOut::Video`). 지금은 이름 충돌이 그 경우이고, 레코드는 실행이 끝나면 지운다(1단계와 같음). 전에는 "the item was not analyzed"로 잘못 알렸다.
- **경고 포함 내보내기·익명화 없이 내보내기:** 처리기가 게시 근거대로 렌더한다. 경고 포함은 track 영역과 고정 마스크를 가리고 gap은 그대로 두며, 익명화 없이는 고정 마스크까지 아무것도 가리지 않는다. 저장한 검토에서 영상을 다시 렌더하는 경로는 3단계라 처리기 수준에서 시험한다.
- **고정 마스크와 track:** 프레임마다 그 프레임의 track 영역(roll 포함) 다음에 고정 마스크를 그린다. 마스크 방식은 사진 기본값(채우기).
- **CLI 시험의 감지기:** 시험 빌드(`synthetic` feature)에 `--fixed-detection X,Y,W,H`를 두어 모델 대신 그 box를 얼굴로 찾게 했다(`--ort-library` 불필요, 타일을 끄고 씀). 모델 경로는 따로 실제 YOLO5Face-n 시험 하나로 본다.

## 흐름

1. 분석(1단계와 같음): 조사·identity·고정 마스크 확인 → 1패스(감지 레코드) → 추적(영역 레코드, track 요약, gap). track이 있으면 결과에 "tracked N faces", 없으면 "nothing detected".
2. runner가 근거로 경로를 정한다: 미해결 근거가 있으면 자동 모드에서도 `NeedsReview`이고 렌더하지 않는다(P-1).
3. **2패스:** 영역 레코드를 한 번 앞에서 읽어 track마다 칸 크기를 정한다(`track_grids`, track 수만큼의 메모리). 인코드 패스(하드웨어 실패 시 소프트웨어로 한 번 더)마다 영역 레코드를 처음부터 다시 읽으며, 원본 프레임 k를 디코드할 때 레코드의 프레임 k를 읽어(번호가 다르면 손상) 그 프레임의 영역 + 고정 마스크를 core 렌더러로 그린다. 영역은 표시 pixel이고 2패스 프레임도 표시 크기라 그대로 쓴다. 홀수 크기 pad(P-5)는 인코더 쪽이다.
4. P-4 검사, 게시(M4와 같음).

## 모자이크 격자

### 실험

실제 track의 box 움직임을 정지 사진(messi5.jpg 1080p, 얼굴 119×145 px)에 옮겨, 공격자가 프레임마다의 칸과 움직임을 안다고 두고 300프레임 전부로 반복 역투영(30회)해 얼굴을 재구성했다. 재구성 RMSE와 같은 RMSE를 내는 블록 평균 크기("유효 칸")로 비교한다(작을수록 많이 복원됨, 한 프레임은 약 20 px). box 움직임은 CC 영상의 315프레임 넘는 track 9개(인터뷰·군중·거리 각 3, 얼굴 크기에 맞춰 0.3–6배)에서 15프레임 이동 평균을 빼 흔들림만 쓴 "정지"와, 이동 평균 경로로 대상을 함께 움직인 "이동" 두 가지다. 강도 8, padding 0.18. 스크립트는 스크래치(`mosaic_attack.py`, `transplant.py`).

| 격자 | 정지 대상 | 이동 대상 |
| --- | --- | --- |
| 프레임마다 box에 맞춘 8칸(사진 규칙, 1.12.1 방식) | 6–17 px | 6–17 |
| track마다 칸 크기 고정, box에 붙임 | 8–15 | 8–15 |
| **track마다 칸 크기 고정, 영상 좌표에 고정(채택)** | **17–23(복원 안 됨)** | 7–14 |

합성 영상(사진에 시간 잡음, 감지기의 흔들림 0.3–2.5 px)에서도 정지일 때 영상 좌표 격자만 한 프레임과 같았다. 대상이 움직이면 어느 격자로도 다중 프레임 복원을 막지 못한다. 기본 방식이 채우기인 이유다(계획 5장). 흔들림이 큰 작은 얼굴을 5–6배로 늘린 track은 흔들림이 실제보다 크게 잡혔을 수 있고, "이동"은 얼굴이 모양을 바꾸지 않고 평행 이동한다는 공격자에게 가장 좋은 가정이다.

### 구현

`Region::grid: Option<MosaicGrid>`. `MosaicGrid::cell_for(box, style, 크기)`가 한 box의 칸을 주고, 2패스가 track의 모든 box 중 가장 큰 값을 쓴다. 칸 값은 영역 복사본이 아니라 그 시점의 영상에서 칸 전체를 읽어 평균한다(앞서 그린 영역 위에 다시 그리는 규칙은 그대로). soft edge 띠의 pixel도 자기 칸을 쓴다. 사용자 이미지 밑의 모자이크도 같은 격자다.

## 시험

- core `mask` 단위 3건 + property: 흔들리는 box 세 개가 같은 격자에서 함께 가린 pixel이 모두 같고 맞춘 칸은 다름, 칸 값이 영역 밖까지 포함한 칸 전체의 평균(영상 가장자리에서 잘림), track 칸이 강도보다 촘촘하지 않음·최소 2 px. 감지 box를 늘 다 가린다는 property 시험에 격자를 무작위로 섞음.
- core `tracking` 단위: 2초 창의 프레임 수(30·60·24 fps, NTSC는 공칭과 같음). legacy fixture `testTrackingWindowsFollowTheFrameRate`의 `changed` 메모 갱신.
- `video_analysis.rs` 9건(흰 사각형 가짜 감지기): 모든 프레임 감지·영역·마스크(1단계의 렌더 거부를 게시와 모든 프레임의 사각형 가림으로), **P-1(영상)** 보간 1초 창에서 30–64 놓침 → gap 30–64·`NeedsReview`·출력 없음·레코드 없음, 상한 후보(프레임 10) → `NeedsReview`, 기본 창에서 같은 놓침 → 게시·모든 프레임 가림·"tracked 1 face", 경고 포함 내보내기(gap 밖은 가림, gap 안 33–61은 드러남)·익명화 없이 내보내기(고정 마스크까지 모두 드러남), 정지 그림에서 box가 흔들려도 모자이크가 프레임마다 같음(lossy 인코드 차이 12 이하; 격자를 빼면 209), 취소·원본 변경·해상도 변경(1단계).
- `video_export.rs` 11건: 고정 마스크 대신 오른쪽 아래 구석을 얼굴로 찾는 가짜 감지기로 바꿔, 감지 → 추적 → 영역 마스크 경로로 프레임 번호·소리·마스크 기준을 그대로 확인. 모든 입력에서 "tracked 1 face".
- `cli_video.rs` 6건: 사진과 P-5 영상을 `--fixed-detection`으로(영상은 "tracked 1 face"·642×362 pad·모든 프레임의 box 가림), 실제 YOLO5Face-n이 astronaut 영상의 얼굴을 찾아 모든 프레임에서 가림, 회전 영상 HEVC(실제 모델 + 고정 마스크), 프레임 밖 마스크, 이름 충돌로 검토에 남는 영상은 세션 없이 "videos cannot be reviewed yet"(종료 코드 3), 사용법 오류(`--mask` 필수 오류는 없앰).
- `d7_sessions.rs`: 사진 4장과 얼굴 영상 하나를 한 실행에, 영상이 이제 게시되고 얼굴 track이 있음(전에는 렌더 거부가 감지가 돈 증거였음).
- `batch` 단위: 검토에 남은 영상은 `LeftOut::Video`.
- `video::process` 단위 2건: track의 칸은 가장 큰 box의 것(track마다 따로), 원본 프레임보다 짧은 영역 레코드는 항목 실패(남은 프레임을 가리지 않은 채 내보내지 않음). `video::analysis` 단위: 임계값·타일·추적 창이 각각 설정 digest를 바꿈(검토 결정이 묶이는 값).

로컬 전체(`cargo test --workspace --locked --all-features`, macOS) 475개 통과(1단계 462개), fmt·clippy 두 조합 통과.
