# 1.12.1과 달라진 동작

Rust 구현이 1.12.1과 다르게 동작하는 점을 한 줄씩 적는다([계획](RUST_PORT_PLAN.md) 7장). 최종 CHANGELOG와 첫 실행 안내의 재료다.

| 영역 | 1.12.1 | 새 동작 | 이유 |
| --- | --- | --- | --- |
| 입력 스캔 | 같은 파일의 하드 링크를 별개 입력으로 처리 | 파일 identity가 같으면 한 입력 | 같은 원본을 두 번 처리해 결과가 둘로 갈라지지 않게 한다. 중복 판정을 identity 한 가지로 정한다(계획 4.3) |
| 입력 스캔 | 대소문자만 다른 경로는 "앱 기준"으로 같은 파일로 봄(D10) | 파일시스템이 같은 파일이라고 할 때만 한 입력. 아직 없는 이름(출력 충돌)은 출력 폴더를 조사해 정함. 정규화를 무시하는 볼륨(APFS·HFS+)에서는 NFC·NFD로만 다른 이름도 같은 이름으로 봄 | 대소문자 구분 볼륨에서 서로 다른 두 파일을 하나로 합치지 않는다 |
| 출력 권한 | 파일 0600, 폴더 0700, Windows는 보호 DACL(D4) | umask와 출력 폴더의 ACL 상속을 따름 | 같은 컴퓨터의 다른 계정·공유 폴더에서 결과를 쓸 수 없었다 |
| 출력 이름 충돌 | 같은 이름의 기존 파일이나 같은 실행의 중복 이름이 있으면 그 항목을 거부 | 덮어쓰지 않는 것은 같고, 검토 화면에서 빈 이름(`photo (2).jpg`)을 제안 | 거부만 하면 사용자가 폴더를 정리하고 다시 실행해야 했다 |
| 출력 폴더 안의 링크 | 출력 폴더 안의 링크를 따라 그 밖에 쓰는 것을 거부 | 링크된 하위 폴더를 따라 그 대상에 씀. 출력 이름 자리에 있는 링크는 끊긴 것이라도 기존 파일로 보고 덮지 않음 | 출력 폴더는 사용자가 고른 곳이고 같은 사용자 권한의 링크 조작은 위협 모델 밖이다. root handle 기준 traversal을 없앴다(계획 0.1) |
| 임시 파일 | 원본 사본을 시스템 임시 폴더의 비공개 stage에 둠(D12) | 원본 사본을 만들지 않고, 출력만 대상 폴더 안의 임시 이름(`.cloakframe-tmp-*`)으로 쓴 뒤 같은 폴더에서 이름을 바꿈. 점으로 시작하는 이름이라 macOS·Linux에서는 숨김 파일이고 Windows에서는 보임. 하루 넘은 남은 임시 파일은 다음 실행이 지움 | 큰 원본에서 디스크 여유 부족 실패가 생기고 사본이 남을 수 있었다 |
| 사진 입력 | CMYK·YCCK JPEG와 CMYK TIFF를 OpenCV의 단순 변환으로 RGB로 바꿔 처리 | 거부("CMYK JPEG/TIFF는 지원하지 않음") | 색 정책(M2 2단계)은 CMYK를 다루지 않으므로 잘못된 색으로 처리하지 않는다. TIFF도 JPEG와 같이 거부한다(2026-10-19, [재검토](M0_M2_REVIEW.md) 6번) |
| 사진 입력 | JPEG 압축 TIFF(스캐너·Photoshop)를 libtiff로 읽어 처리 | 거부("JPEG 압축 TIFF는 지원하지 않음") | 쓰는 TIFF 디코더가 YCbCr JPEG strip을 읽지 못하고, RGB로 잘못 표기된 파일은 엉뚱한 pixel로 디코드한다([재검토](M0_M2_REVIEW.md) 4번). 지원은 수요를 보고 strip을 libjpeg-turbo로 디코드하는 방식으로 정한다 |
| 사진 색(D2) | ICC profile을 버리고 pixel을 그대로 써서 wide gamut 사진의 색이 틀어짐 | sRGB·Display P3·Adobe RGB는 pixel을 그대로 두고 번들 표준 profile을 붙임. 그 밖의 profile은 sRGB로(회색 사진의 회색 profile은 sRGB 곡선의 회색으로) 변환하고 결과에 표시. 읽을 수 없는 profile은 버리고 표시 | 결과 사진의 색이 원본과 같게 보이도록 한다 |
| BMP 색(D2) | BMP의 ICC profile을 읽지도 쓰지도 않음 | BMP V5에 내장된 profile을 읽어 D2를 적용(다른 파일을 가리키는 profile은 버리고 표시). BMP 출력에는 profile을 붙이지 않으므로 Display P3·Adobe RGB 사진은 sRGB로 변환하고 표시 | macOS 미리보기·Quick Look이 profile을 내장한 BMP를 열지 못한다 |
| 모자이크(D3) | 픽셀 단위 블록 크기(기본 14px), 셀 수 12개 상한 때문에 큰 얼굴에서는 설정이 무효 | "강도" 4–12(기본 8): 영역 짧은 변에 들어가는 셀 수. 셀 값은 셀 영역의 평균. 작은 영역에서도 셀은 최소 2px | 범위 안의 모든 설정이 결과를 바꾸게 한다 |
| 블러 | sigma = 짧은 변 / 6, 영역 안 pixel만 커널에 씀. 2px 미만 영역은 평균색으로 채움 | sigma는 같고 하한 4px. 영역 밖 pixel도 커널에 넣어 가장자리까지 같은 정도로 흐림 | 작은·얇은 영역과 영역 가장자리에 세부가 남지 않게 한다(계획 5장) |
| 기본 가리기 방식 | 모자이크 | 단색 채우기 | 계획 5장 |
| 타원 마스크 | 안티앨리어싱 타원이 닿은 pixel | 한 pixel 키운 타원이 닿은 pixel. 1.12.1이 가린 pixel은 모두 가림 | OpenCV 래스터화를 옮기지 않고 같은 이상을 가린다 |
| soft edge | 영역 크기를 4px 배수로 올려 계산, 타원 경계 ramp가 고르지 않음 | 영역 크기 그대로, 타원 ramp는 중심에서 잰 거리로 매끄럽게. 사각형 결과는 1.12.1과 같음 | 마스크 캐시를 없애 4px 정렬이 필요 없다 |
| 사진 인코딩(D6) | JPEG q100 4:4:4, WebP는 무손실(원본이 손실이어도) | JPEG q92·원본 크로마 서브샘플링(원본이 JPEG가 아니거나 libjpeg-turbo가 쓸 수 없는 조합이면 4:4:4), 손실 WebP 원본은 손실 q90. PNG·무손실 WebP·TIFF(LZW)는 무손실 그대로 | 출력이 원본보다 2–12배 커지지 않게 한다 |
| 원본 복사(D9) | "원본 복사" + 메타데이터 보존이면 파일을 바이트 그대로 복사(GPS·시리얼 포함) | 원본 복사 없음. "익명화 없이 내보내기"는 검토에서 항목별로 고르고, 같은 메타데이터 규칙으로 다시 인코딩하며, 정상 완료 수에 넣지 않음 | 바이트 복사는 금지 메타데이터를 그대로 남긴다 |
| 감지 후보 | NMS 전에 점수 상위 2,000개만 남김. 군중 사진에서 얼굴을 놓침(D11 fixture: 280개 중 259개). YuNet은 OpenCV `FaceDetectorYN`의 상위 5,000개 | 모든 후보로 NMS(YOLO5Face-n은 출력 25,200행, YuNet은 격자 8,400칸이 상한). NMS 뒤 감지 수 상한(1.12.1은 300)도 없어 사진은 NMS를 통과한 감지를 모두 가림 | 상한이 실제 얼굴을 버렸다. NMS는 최악에도 약 0.3초이고, 마스크 비용은 box 수가 아니라 가리는 면적을 따른다(계획 D11) |
| GPU 가속 | YuNet은 OpenCV로 CPU에서만 실행. 가속 실패는 로드 때 검은 그림 시험 실행으로 확인해 CPU로 바꾸고, 실행 중 실패하면 그 파일부터 CPU로 바꾸며 로그만 남김 | macOS에서 YuNet도 CoreML(번호판은 CPU, 1.12.1도 로드 시험에서 CPU로 감). 로드 시험 실행은 없고, 세션을 못 만들면 CPU로 시작하며 사진이 GPU에서 실패하면 그 사진을 CPU로 다시 분석해 결과에 표시("the GPU failed; analyzed again on the CPU"). 실행 위치는 검토 결정을 막지 않음 | YuNet은 CoreML에서 결과가 같고 2.5배 빠르다. 폴백 경로를 하나로 줄이고 어느 항목에서 일어났는지 보이게 한다([기록](M3_EP.md)) |
| 모델 폴더 권한(D5) | 다른 계정이 쓸 수 있는 모델 폴더(umask 002 등)면 받은 모델을 저장하지 않음 | 폴더 권한을 보지 않고 저장. 모델은 로드할 때 해시로 확인 | 같은 사용자 권한의 변경은 위협 모델 밖이고 바뀐 파일은 해시로 막힌다(계획 0.1·5장) |
| 모델 위치 | 앱 데이터의 `CloakFrame/models`·`Redactly/models`, 앱 옆·번들 안·작업 폴더의 `models` 등 여섯 곳에서 처음 찾은 파일 | 앱 모델 폴더 하나(macOS·Windows는 1.12.1과 같은 폴더). Linux의 `CloakFrame/models`와 세 OS의 `Redactly/models`에 있는 모델은 새 폴더에 없을 때 해시를 확인해 복사하고 원본은 둠 | 어느 파일이 쓰이는지 한 곳으로 정한다. Linux 폴더 이름은 XDG 관례대로 소문자다([기록](M3_MODELS.md)) |
| 모델 로드 시점(D7) | 입력을 스캔하기 전에 모델을 불러, 처리할 파일이 없어도 모델이 없으면 실행 실패 | 스캔에서 처리할 파일이 나온 뒤 그 실행이 쓰는 모델만, 모델·입력 크기·실행 위치마다 세션 하나 | 쓸 일 없는 모델 때문에 실패하지 않고 같은 모델을 두 번 불러오지 않는다 |
| 모델 다운로드 | 어느 HTTPS 주소로든 redirect를 따라감, 일시 오류는 1초 뒤 세 번까지 다시 시도, 30초 동안 데이터가 없으면 중단 | GitHub와 그 다운로드 호스트(`release-assets.`·`objects.`·`media.githubusercontent.com`)로 가는 HTTPS redirect만, 자동 재시도 없음, 연결·응답 30초와 전체 15분 한도(데이터가 멈추면 15분까지 기다림) | 고정 URL의 호스트 밖으로 나가지 않는다(계획 3장 allowlist). 실패하면 사용자가 다시 받는다 |
| 모델 이용 조건 | 다운로드마다 대화상자로 조건을 보여 주고 예·아니요 | CLI `models`가 조건을 보여 주고, `models fetch`는 받기 전에 조건을 출력하며 비상업 전용 YOLO5Face-n은 `--accept-terms` 없이는 받지 않음(앱 화면은 M6) | 대화상자가 없는 CLI에서도 조건 확인 없이 비상업 모델을 받지 않게 한다 |
| CoreML 컴파일 캐시 | `~/Library/Caches/CloakFrame/CloakFrame/coreml-models/<모델 해시>`, 현재 것이 아니고 60일 넘게 바뀌지 않은 폴더만 지움 | `~/Library/Caches/CloakFrame/coreml/<ORT 빌드>/<모델 해시>`. 실행이 시작할 때 이 빌드가 쓰지 않는 폴더를 바로 지우고 1.12.1의 캐시 폴더도 지움 | 고정 모델과 ORT 빌드만 쓰므로 나머지는 다시 읽히지 않는다. 다른 판을 동시에 돌리면 그 판이 다시 컴파일한다 |
| 번호판 NMS | 모델 그래프 안의 NMS가 번호판을 최대 100개, IoU 0.45로 남기고 NMS 설정은 무시 | 그래프의 상한과 IoU를 풀고 번호판 NMS 임계값(기본 0.45)으로 engine이 NMS. 100개 이하에서는 결과가 같음 | 상한이 모델이 찾은 번호판을 버릴 수 있고(D11), 번호판 NMS 설정이 적용되지 않았다(P-2). [기록](M3_DETECTION.md) |
| 감지 임계값(P-2) | 얼굴과 번호판이 score·NMS 임계값 한 쌍을 공유(번호판은 NMS를 쓰지 않음) | 종류별 임계값. 기본값은 1.12.1이 실제로 쓴 값(얼굴 score 0.5·NMS 0.4, 번호판 score 0.5·NMS 0.45) | 두 모델의 점수 분포가 다르다. 기본값은 라벨 벤치마크(계획 9.2)로 확인해 유지했다([기록](M3_BENCHMARK.md)) |
| 미해결 감지 문제(P-1) | 감지 수 상한을 넘은 사진도 경고와 함께 저장(넘은 감지는 가리지 않음) | 저장하지 않고 검토를 기다림. 검토에서 "경고 포함 내보내기"를 고른 항목만 저장하고 정상 완료 수에 넣지 않음 | 가려지지 않은 얼굴이 있을 수 있는 결과가 정상 출력처럼 남았다 |
| 작은 얼굴 감지 | 사진을 640 px 입력에 맞춰 한 번만 봄. 4000×3000 사진에서 약 128 px 미만 얼굴을 놓침 | 타일 모드 기본 켬: 전체 보기에 더해 원본 배율 1까지 겹치는 640 px 타일을 층마다 보고 합침. 원본 40 px 이상 얼굴을 찾음(합성 12MP 사진 96개 중 6–22개 → 60–66개, 실제 사진 203장에서 라벨 얼굴 재현율 82.3% → 87.2%). 성긴 보기에서도 찾을 만한 크기인데 거기서 찾지 못한 저점수 타일 감지는 버림. 그래도 확대한 질감(물방울·철망·글자)을 얼굴로 잘못 가리는 일이 사진당 약 0.03개에서 0.23개로 늘어남. 12MP 사진 한 장에 CoreML 약 0.9초, CPU 약 1.7초가 더 듦. CLI `--tiles off`로 끔 | 놓친 작은 얼굴이 "자동 처리·미검토"로 게시되지 않게 한다([기록](M3_TILES.md), [오탐 조사](M3_TILE_FALSE_DETECTIONS.md)) |
| 감지 0건 사진 | "가린 영역 없음" 경고와 함께 저장(실행 결과 "경고 포함 완료") | 다른 사진처럼 저장. 자동 모드에서는 "자동 처리·미검토"이고 결과에 "감지 0건"(nothing detected)을 표시 | 감지 0건은 미해결 문제가 아니다(계획 4.2). 놓친 작은 얼굴이 조용히 지나가지 않게 표시하고, 검토 화면이 따로 모아 보여 준다(M6) |
| 감지 없이 실행 | 얼굴 감지를 끄면 아무것도 가리지 않은 결과를 경고와 함께 저장 | CLI 실행에는 감지 모델이 필요. 가리지 않은 결과는 검토의 "익명화 없이 내보내기"로만 만듦 | 감지 없이 만든 결과가 정상 출력처럼 보이지 않게 한다(P-1) |
