# 1.12.1과 달라진 동작

Rust 구현이 1.12.1과 다르게 동작하는 점을 한 줄씩 적는다([계획](RUST_PORT_PLAN.md) 7장). 최종 CHANGELOG와 첫 실행 안내의 재료다.

| 영역 | 1.12.1 | 새 동작 | 이유 |
| --- | --- | --- | --- |
| 입력 스캔 | 같은 파일의 하드 링크를 별개 입력으로 처리 | 파일 identity가 같으면 한 입력 | 같은 원본을 두 번 처리해 결과가 둘로 갈라지지 않게 한다. 중복 판정을 identity 한 가지로 정한다(계획 4.3) |
| 입력 스캔 | 대소문자만 다른 경로는 "앱 기준"으로 같은 파일로 봄(D10) | 파일시스템이 같은 파일이라고 할 때만 한 입력. 아직 없는 이름(출력 충돌)은 출력 폴더를 조사해 정함 | 대소문자 구분 볼륨에서 서로 다른 두 파일을 하나로 합치지 않는다 |
| 출력 권한 | 파일 0600, 폴더 0700, Windows는 보호 DACL(D4) | umask와 출력 폴더의 ACL 상속을 따름 | 같은 컴퓨터의 다른 계정·공유 폴더에서 결과를 쓸 수 없었다 |
| 출력 이름 충돌 | 같은 이름의 기존 파일이나 같은 실행의 중복 이름이 있으면 그 항목을 거부 | 덮어쓰지 않는 것은 같고, 검토 화면에서 빈 이름(`photo (2).jpg`)을 제안 | 거부만 하면 사용자가 폴더를 정리하고 다시 실행해야 했다 |
| 임시 파일 | 원본 사본을 시스템 임시 폴더의 비공개 stage에 둠(D12) | 원본 사본을 만들지 않고, 출력만 대상 폴더 안의 숨김 임시 파일로 쓴 뒤 같은 폴더에서 이름을 바꿈. 하루 넘은 남은 임시 파일은 다음 실행이 지움 | 큰 원본에서 디스크 여유 부족 실패가 생기고 사본이 남을 수 있었다 |
| 사진 입력 | CMYK·YCCK JPEG를 OpenCV의 단순 변환으로 RGB로 바꿔 처리 | 거부("CMYK JPEG는 지원하지 않음") | 색 정책(M2 2단계)이 CMYK를 다루기 전까지 잘못된 색으로 처리하지 않는다. 2단계에서 다시 정한다 |
